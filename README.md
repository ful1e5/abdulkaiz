# abdulkaiz.com

Static site (plain HTML/CSS/JS) that renders its content from `content/*.json`.
Optional Cloudflare Pages Functions in `functions/api/*` add email delivery and
region-aware pricing; on plain static hosts (GitHub Pages, S3, etc.) the site
still works using its client-side fallbacks.

Production host: **https://ful1e5.github.io/abdulkaiz/**

## Content

Everything visible on the site comes from four JSON files, all directly editable:

| File                        | Drives                                                                                                          |
| --------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `content/site.json`         | Contact details, intro video, About copy, stats, services, process, experience, education, hero logos, headings |
| `content/portfolio.json`    | Portfolio projects and the homepage marquee                                                                     |
| `content/testimonials.json` | Client reviews                                                                                                  |
| `content/pricing.json`      | Pricing packages, retainers and regional multipliers                                                            |

## Pages and URLs

Each page is a directory with an `index.html`, so the URL carries no `.html`:

| File                      | Served at                  |
| ------------------------- | -------------------------- |
| `index.html`              | `/abdulkaiz/`              |
| `portfolio/index.html`    | `/abdulkaiz/portfolio/`    |
| `testimonials/index.html` | `/abdulkaiz/testimonials/` |
| `about/index.html`        | `/abdulkaiz/about/`        |

There are deliberately **no** `about.html` / `portfolio.html` /
`testimonials.html` files. GitHub Pages prefers a file over a directory for an
extensionless URL, so a stub at `about.html` gets served for `/abdulkaiz/about`
— the visitor lands on the stub instead of the page. With the directory as the
only match, `/abdulkaiz/about` 301-redirects to `/abdulkaiz/about/` and renders
About.

The cost is that the old `/abdulkaiz/about.html` URLs now 404 instead of
redirecting. That is the better trade here: the site is not yet indexed (its
canonical host was a dead domain until recently), so there is no accumulated
link equity to preserve, and the no-trailing-slash form is one people actually
type. Do not re-add stubs "for SEO" — they reintroduce the bug.

### Why a `<base>` tag

Every asset reference is relative (`style.css`, `content/site.json`,
`assets/…`). One directory deeper they would all break, so each sub-page carries
`<base href="../" />` as the first element in `<head>`. Every relative URL then
resolves against the site root from any depth, and the same markup works whether
the site is served from `/abdulkaiz/` or from a bare domain root.

`script.js` resolves its link interception against `document.baseURI` rather
than `location.href` — resolving against `location.href` would defeat the base
tag on the sub-pages.

## Building

```bash
python3 build.py           # generate, then commit the output
python3 build.py --check   # report stale output; non-zero if anything differs
```

Because GitHub Pages deploys from the branch, generated output is committed:
edit source → `python3 build.py` → commit. The script only fills marked regions
and writes its own files; everything else in a page is left byte-for-byte alone,
so a second run produces no diff.

`build.py` fills `<!--#nav-->`, `<!--#footer-->`, `<!--#fonts-->` and the two
`<!--#photo-…-->` regions, and generates `sitemap.xml`, `robots.txt` and
`content/seed.js`. Nav and footer markup lives once, in `templates/`.

Nav and footer are **rendered into the HTML**, not injected by JavaScript. Before
that change the raw HTML contained no internal links at all, leaving `portfolio`,
`testimonials` and `about` unreachable to any crawler that does not run JS.

`content/seed.js` is an offline fallback, loaded lazily only if a JSON request
fails — it used to load on every page and then be superseded by those same
fetches. `content/seed.js` is regenerated by `build.py`; edit the JSON, not it.

## Derived assets

Three scripts regenerate binary/vendored assets. All are committed, and each is
only needed when its source changes:

```bash
python3 tools/images.py    # portrait variants (avif/webp/jpg) — needs ImageMagick
python3 tools/fonts.py     # self-hosted font subsets — needs fontTools + network
python3 tools/social.py    # assets/og.png share card — needs Pillow + fontTools
```

- **Portrait** — the master is `assets/uploads/Abdulkaiz Potrait.png` (1.0 MB).
  `tools/images.py` bakes in the grayscale and contrast that used to be a CSS
  filter and emits 400/700/1000px AVIF + WebP plus a JPEG fallback: **6.8 KB for
  the mobile variant**. Because the treatment is baked in, **do not swap in a
  colour photo without re-running the script.**
- **Fonts** — `tools/fonts.py` replaces the two render-blocking Google Fonts
  stylesheets with self-hosted subsets (~29 KB total). Google serves DM Sans as
  a single variable font for every weight, so it is de-duplicated to one file
  with a `font-weight: 400 700` range rather than four identical copies.
- **Share card** — `tools/social.py` renders `assets/og.png` (1200×630) in the
  site's own Poppins. It uses Pillow, not `magick -annotate`: ImageMagick cannot
  use the TTFs fontTools produces here and fails _silently_ — exit 0, no warning,
  and a card with no text on it. The script refuses to write a textless card.

## Hosting flag

`build.py` sets `data-functions="yes|no"` on `<html>` from its `HAS_FUNCTIONS`
constant. It is `False` for GitHub Pages. The region endpoint only exists where
the Pages Functions are deployed; on a static host it 404s, and Chrome logging
that failed request was the sole cause of the Best Practices score reading 96
instead of 100. Set `HAS_FUNCTIONS = True` when deploying to Cloudflare Pages.

## Deploy

### GitHub Pages (current)

Serve the repository root. A `.nojekyll` file is included so the tree is
published as-is. On this host:

- the contact form opens the visitor's email app with the message prefilled (no
  server needed);
- regional pricing falls back to the visitor's timezone/locale instead of
  geo-detection.

### Cloudflare Pages (full features)

Connect the repo. Build command: `python3 build.py` (optional) or leave empty.
Output directory: `/`. Set `HAS_FUNCTIONS = True` in `build.py` first.

## Contact form (Cloudflare Pages only)

Stores every message and emails a copy. In the Pages project settings:

1. **KV** — create a namespace (e.g. `leads`) and bind it as `LEADS`. Each
   message is stored as `lead:<time>:<id>`; a per-IP rate-limit key is set for
   60 seconds.
2. **Email** via [Resend](https://resend.com) — set `RESEND_API_KEY` (secret),
   `TO_EMAIL`, and `FROM_EMAIL` (e.g. `Website <hello@abdulkaiz.com>`).
3. Redeploy. If both storage and email fail, the visitor sees an error with the
   email address as a fallback.

Deployed without those variables, the form degrades to the same mailto fallback
used on static hosts.

## Local preview

```bash
python3 -m http.server 8000 --directory ..   # then open /abdulkaiz/
npx wrangler pages dev .                     # full local parity with Cloudflare Pages
```

Serve from the **parent** directory and visit `/abdulkaiz/`, so the real base
path is reproduced — serving the repo root directly would resolve the sub-page
`<base>` tags against the wrong root.

## Known remaining issue

`/testimonials/` shows a cumulative layout shift around 0.145. The twelve review
cards are built by JavaScript into a height-driven multi-column grid, so the
footer sits high on first paint and is then pushed down. There is no CSS
reservation that fixes this without leaving visible gaps; the real fix is to
render the reviews into the HTML at build time, the way the nav and footer now
are.
